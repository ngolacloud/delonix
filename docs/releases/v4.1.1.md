## v4.1.1 — security hardening, `vm destroy`, and a cluster's CRI no longer comes from the cwd

Fifty-two commits since `v4.1.0`, numbered as a PATCH by the owner's decision. Honesty
note: the series includes new surface area (`vm destroy`,
`--rm`/`--rm-after`, `--cri-bin` on `cluster`), which by the repo's convention would be
a MINOR — stated here so no one reads "patch" as "fixes only."

### Security

- **`vm migrate`**: shell injection and a namespace-isolation collision
  fixed (CRITICAL, `6bedce83`).
- **`kubeadm join`**: values read from remote output are validated before
  reaching a shell, and OCI manifests now have a size ceiling.
- **A cluster's `metadata.name`** and a kind cluster's name are validated
  before composing paths (a name with `..` wrote etcd's CA outside the state
  root); `Service`/`NetworkRoute` records are now injective.
- **The CRI's `ExecSync`** and `fetch-media.sh` gain a size ceiling; five
  LOW hardenings (VM cache, `COPY --from`, control socket, download
  resumption, Proxmox).

### Cluster: the runtime's origin is whichever the operator chose (#242, #243)

- **#242** — `prepare_host` only compared "is the service alive?", so the
  golden's `delonix-cri` always won and a fix never reached an existing
  node. It now compares the `sha256`: same and alive → nothing; same and stopped →
  starts it; different → replaces it, restarts it, and says so.
- **#243** — `resolve_cri_bin` no longer compiles whatever source happens to be
  near the cwd. Only with `DELONIX_CRI_FROM_SOURCE=1`; by default it uses the
  `delonix-cri` next to `delonix` and then the release's verified asset. Provenance
  (origin, path, `sha256`) is always printed. `cluster apply` and `cluster kubeadm`
  gain `--cri-bin`.

### VMs

- **`vm destroy`** — complete teardown across providers; exits with the failure's class and
  removes the store's lock file; `vm prune` no longer swallows failures.
- **`vm create --rm` / `--rm-after`** — disposable VMs; the timer takes down
  the state root, is disarmed by `vm destroy`, and is not re-armed by `vm ls`. Ctrl+D
  at the console.
- libvirt's cloud-init seed now goes on a virtio disk instead of a SATA cdrom.

### Stack and Kinds

- A `kind: Stack`'s groups leave the Kinds table (ADR-0045); the groups for
  removed Kinds (`storage`/`shareVolumes`/`egress`) leave too.
- `metadata.labels` reaches the container, and because of that a `Service` now matches.
- Closing a route whose nft element no longer exists is a success, not an error.
- Full examples per Kind (`full-<kind>.yaml`) and the regenerated site.

### Not validated

- The CRI substitution in `prepare_host` **was not run against a real node over
  SSH** — only the local comparison command and the decision tests.
- `vm destroy`/`--rm-after` was validated by tests and by isolated runs; not
  in a full battery against real Proxmox/OpenStack.
- See this release's report for the `scripts/e2e.sh` result.
