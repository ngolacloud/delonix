## v5.1.0 — what the engine cannot enforce it now refuses, and the projects it generates are born with a gate

Two hundred and eighty-nine commits since `v5.0.2` (197 not counting merges),
from `#723` to `#843` — measured at `a46095a3`
(`git rev-list --count v5.0.2..a46095a3`). The number travels with the commit it
was measured at: without that it ages silently as `main` grows.

**MINOR, and the reason is verifiable**: nothing in this release breaks a
contract that any version declared. The new refusals (there are many) all land
on requests the engine **could no longer fulfil** and reported as success, or
on surfaces that `docs/cli-stability.md` lists as «no promise declared in any
version» — `init` among them.

The thread is the same as the last two releases, now pushed into the places
where there was still a cheap yes: **what the engine cannot enforce, it
refuses; what it does not understand, it does not swallow; and what it has not
measured, it does not claim.** The novelty is that this has reached what the
engine **generates** — a project born from `delonix init` now comes with
tests, two CIs, Conventional Commits, SonarQube and a README that advises on
architecture, with a gate requiring it.

---

### Read before upgrading

None of these is a break of a declared contract, but the four change what a
command that returns `0` today does tomorrow.

- **The CRI now has a capabilities ceiling BY DEFAULT** (`#828`). Without
  configuration, the ceiling is the engine's `KEPT_CAPS` in `reject` mode: a
  normal pod runs as before, and `privileged: true` or a `capabilities.add`
  above that set are **refused on `CreateContainer`**. Absent or empty no
  longer means «no ceiling» — the only way out is to write it
  (`DELONIX_CRI_CAP_CEILING=all`), and an invalid value or mode stops the
  server from starting rather than falling back to «unlimited».
- **`delonix vm image <verb>` is the only path** (`#772`). `image vm …`,
  `image --vm …` and the flat forms `vm build|convert|pull|push|ls-remote` fail
  with `unrecognized subcommand`. A clean cut, no alias: the `vm` group is on
  the non-stable list.
- **`delonix init` refuses more than it used to** (`#842`, `#843`): a port
  this host cannot publish stops `--up` **before** the build; an
  `init -t <other>` over a directory that already has another project is a
  conflict (exit 5) instead of «nothing to do» followed by a build of the
  wrong project; and an unknown key in `template.meta` stops the engine's own
  build.
- **`cluster kubeadm` refuses the default CNI on a multi-node cluster**
  (`#810`), before creating a single VM. Previously it provisioned everything
  and the cluster was left with no network between nodes.

### A generated project is born with a gate (`#842`, `#843`)

It started with a production bug: `delonix init -t nginx --port 9000 --tls-port 943`
generated the project and `build` **always** died with `nginx: [emerg] bind()
to 0.0.0.0:943 failed (13: Permission denied)`, at the step that was only
supposed to check the configuration syntax.

Four measurements, and each one changed the fix:

1. the `build`'s working container runs in the HOST's netns (same inode),
   where the engine's userns does not have `CAP_NET_BIND_SERVICE`;
2. `nginx -t` **binds** every `listen` it reads — it is not a parser;
3. and it tolerates `EADDRINUSE`: **only `EACCES` is fatal**, so the obvious
   gate («occupy the port and build») would pass over the defective binary;
4. only nginx has the problem — `httpd -t` and `haproxy -c` built with the
   same ports without a single complaint.

The check now runs over a copy whose two `listen` directives are unix sockets.
The port itself was never actually unusable: inside the container's own netns
the same `listen 943` returns `rc=0`.

**The eleven templates were then generated with the adversarial port and
built: 11/11.** The sweep found another defect, which remains **open** and is
written down: `init -t go ./go` generates, with exit 0, a `go` module that Go
refuses, and `-t django ./django` a package that depends on itself.

And the templates' contract gained a gate. Before, `nginx`, `httpd`, `haproxy`
and `odoo` had **zero** CI, SonarQube and `CONTRIBUTING.md`; `nestjs` had lost
the `commitlint` the two siblings have; and none of the eleven had an
architecture section in the README. Now all of them do, two tests require it,
and `scripts/init-ci.sh` **runs** the generated CI of all eleven — the GitLab
job and the GitHub steps on the seven application ones, `ci-check.sh` on the
three edge ones (which builds the image and probes it **from the outside**,
the only way the smoke test itself is honest) and `pre-commit` on `odoo`.

Running that CI instead of reading it found three bugs in the generated
projects: the `smoke.sh` of the three edge ones **ignored** the URLs it
receives as an argument (`127.0.0.1` hardcoded, so it FAILs against any
correct server outside the loopback); a `haproxy` check required a
delonix-managed container and now **skips with the reason**; and the OCA's
`prettier` reformatted the files that `init` generates, failing `odoo`'s gate
on an untouched project.

### Security

- **Every layer extraction now has a ceiling** (`#828`, `#788`): entry count
  and decompressed bytes, against a decompression bomb, and every path
  confined.
- **A foreign setuid bit is dropped during extraction as real root**
  (`#800`).
- **The admission gate fails CLOSED on a scan FAILURE** (`#778`) — not only on
  a scan result with findings. The distinction is the one that matters: «I
  could not analyse» is not «it is clean».
- **An optional guard keeps workloads out of private space and CGNAT behind
  the uplink** (`#819`): `denyPrivateEgress` in node policy, off by default,
  with per-prefix concessions. It lives in its own chain before everything
  else, so neither a network `allowlist:` nor an `egress allow` reopens it.
- **`cluster apply` can pin the SSH host key** instead of trusting first
  connection (`#796`), opt-in.
- **An admission that restricts nothing is LOGGED as such** (`#767`).
- **`install.sh` checks user namespaces through delonix's own AppArmor
  profile** (`#775`), which is the real path — not generically.
- Dependency advisories: `rustls` 0.23.46 (`#839`), `unsafe-libyaml` named
  with the reason (`#833`).

### Kubernetes (CRI)

- **`cpuset_mems`, `unified` and `hugepage_limits`**: honour-or-refuse, with
  the probe done on the cgroup where the container will ACTUALLY live
  (ADR-0038 item 3, `#752`).
- **`UpdateContainerResources` implemented** and location-aware (ADR-0038
  item 4, `#755`): under a kubelet scope these are systemd properties,
  outside it they are written on the leaf, and the merge is field by field —
  «unspecified» on an update means «do not touch», not «no limit».
- **A partial `cpu_quota`/`cpu_period` is refused** instead of writing an
  absurd CPU limit (`#766`).
- **A hugepage ceiling of zero over an empty pool is not a request**
  (`#787`).
- **`serve cri` warns loudly when there is no capabilities ceiling** (`#794`),
  and names **the engine's error**, not the progress line before it (`#795`).
- ADR-0062's root fallback reaches `ContainerStatus.info` (`#750`).

### VMs

- **Hot-plug of CPU and memory**: Cloud Hypervisor (ADR-0068 phase 1, `#749`)
  and, next, libvirt and Proxmox, with a shape change to **restart instead of
  replace** the VM (ADR-0012/ADR-0068, `#831`) — `Replace` threw away the
  overlay disk.
- **VMaaS readiness** (`#741`): guest agent, `vm ssh` fixed in the netns, and
  `vm.disk.resize`.
- **`etcd` backup/restore** for a stacked control plane provisioned in a VM
  (`#747`).
- **A cloud-init VM on Proxmox gains the serial port that `console=ttyS0`
  boots on** (`#781`) — without it the first boot panicked.
- **Live assessment of capabilities** of Proxmox and Cloud Hypervisor
  (`#744`, `#742`), with the vnet firewall token index fix.
- **A live test that does not run no longer passes silently** (`#779`,
  `#802`): it is `#[ignore]`, and a gate keeps it that way.

### Node API

- **`VirtualMachineService` served** (ADR-0040 P5, `#746`), and the resolution
  of the vCPU/memory/backend defaults that the image itself declares (`#763`).
- **Socket activation and exit on idle** (ADR-0040 P5, `#822`).
- **A race in the operations ledger and idempotency identity** fixed
  (`#762`, ADR-0076 in `#765`).
- Step E of ADR-0042 validated live through the socket (`#814`).

### Networking, IPAM and DNS

- **A zone names its IPAM controller, and subnets change in place**
  (ADR-0063 D1/D2, `#754`): the gateway and the ranges became hot fields, and
  a gateway entry moved by a rollback is repaired.
- **The plan reads IPAM's gateway entries** (`#834`): before, an entry freed
  by hand planned «no changes».
- **A zone reservation can name a workload that is a VM** (ADR-0063 D3.3,
  `#768`).
- **The engine cleans up the gateway records a Proxmox node leaves behind**
  (ADR-0064 D6, `#758`), and vnet firewall writes now **refuse
  unconditionally** instead of failing halfway (`#757`).
- **A network route is usable from an additional network** (`#733`).
- **A failed boot no longer tears down the network of a container that is
  running** (`#801`).

### Storage

- **Storage pools** (ADR-0067 P1–P4/P6, `#830`): the socket-activated root
  helper and the `btrfs`, `zfs` and `lvm-thin` drivers, with marked ownership
  and refusal above 95%.
- **Shrinking a hard quota refuses a usage that could not be measured**
  (`#782`) — unknown is never zero.

### Compose, Docker API and CLI

- **Compose against a real sample, service credentials** (ADR-0048 phase 3)
  **and the Docker API at Testcontainers level** (`#821`).
- **`container ps` without `-a` lists only what is running**, and the Docker
  API honours `all` and returns ports (`#816`).
- **`vm image <verb>`** as the single entry point (`#772`).
- **The VMfile's `COPY` keeps the meaning it has in a Dockerfile** (`#783`).
- **`secret rotate-key` no longer rolls the version back** (ACH-034, `#723`)
  — rotating the master key does not change any value, and it was setting
  every version back to 1.
- **The MCP's `audit.query` logs the call itself**, like the others (`#780`).

### Engine robustness

- **`spawn()` was split into named steps, with continuous fuzzing — and that
  found two defects** (`#829`).
- **A container that exceeded the mount ceiling is never entered** (`#813`).

### The assembly line

- **`protoc` is pinned and checked** on both release jobs and the eight CI
  ones, in a single local action (`#728`, `#730`, `#731`) — v5.0.0 failed on
  its first attempt because `ubuntu-22.04` ships 3.12 and the CI pinned a
  different runner.
- **The generated documentation's markdown renderer is pinned** (`#840`).
- **The ADR state gate reads the index in bullets** — and four were lying
  (`#732`, `#739`).
- **`vm-image.yml` called a flag that had been removed**, and its `no_k8s`
  branch never ran at all (`#743`, `#745`, `#748`).

### Measured coverage

The fraction of CLI leaves the battery **runs and judges** (not just calls
`--help` on) went from **126/272** to **258/270 — 95.6%** over the series
(`#721`, `#722`, `#761`, `#811`, `#818`), with a ratchet holding it in both
directions and the numerator coming from a committed trace, with provenance
and date.
Alongside: the battery measures that the sibling being served is from the
`$BIN`'s own release (`#725`), that a state root written by the previous
release opens unchanged (`#777`), and that teardown waits for `DX-8101` and
says what it could not remove (`#832`, `#837`).

### What this release does NOT close

- **A project name that collides with the framework's own** still generates,
  with exit 0, a project that does not build (`init -t go ./go`).
- **`release.yml` is still exercised by nothing**: zero references in
  `ci.yml`'s jobs, in `scripts/` and in tests. A broken reference there only
  shows up on the next `gh workflow run`.
- **OpenStack still has no backend** — ADR-0039, *Proposed*, and
  `provider.type: openstack` is refused at load.
