## ⚠️ DEF-003 — ROOT-CAUSED, but it is NOT contention (I did not pause kind/ceph)

Re-tested in an **isolated** `DELONIX_ROOT`+network: `compose up`/`run --net
<custom>` **hangs** (exit 124), creates 0 containers. Diagnosis from the process
tree:

- `delonix run` → `do_wait` (waits for a child);
- children: `delonix netns pin` (`pause()`), `netns control`
  (`__skb_wait_for_more_packets`), `slirp4netns` (poll), and **`delonix netns run`
  sometimes in `locks_lock_inode_wait` (FILE-LOCK wait), sometimes in `anon_pipe_read`
  (waiting for a child's output)**.

**Conclusion:** the custom-network attach has a step (slirp-ready / DHCP lease /
serialization lock) that **does not complete in this host state and has NO timeout
→ hangs indefinitely**. Since it **reproduces in an isolated root+network, under low
load (load 3.4) and with named `netns` = 0**, it is **NOT kind/ceph contention** — so
pausing them (authorized) would be useless and I did not do it. There is an owner's `slirp4netns`
alive for ~12 h (from `travel-pg`).

- **Product finding (P2/robustness):** the network attach should **bound each
  wait and fail with an error**, never hang forever.
- **To actually close DEF-003:** a dedicated session with `strace` on `netns
  run`/`slirp4netns` and, preferably, a **clean/rebooted host** (to
  rule out a host-global lock leaked by the owner's 12 h network process).

   `/var/lib/delonix` + `/etc/delonix`** (data intact), named the shared
   host config that it leaves alone.
5. **Purge** (`install.sh --uninstall --purge`): removed state+config; shared host
